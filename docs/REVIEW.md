## 已修复的问题

| 问题 | 修复后的行为 |
|------|--------------|
| 游戏引擎直接按外部玩家编号访问数组，且下注未统一校验回合、阶段和筹码 | 引擎统一验证合法操作；拒绝越界编号、自比、非本回合操作、负数或超额下注，防止负筹码和重复结算 |
| 空手牌的牌型可能未初始化；两个特殊 235 比较时双方都被判负 | 空手牌安全处理，235 比较恢复对称性，同点数卡牌排序稳定 |
| 看牌后的跟注被记为加注；手机端仍显示蒙牌金额 | 依据操作前的跟注额区分跟注与加注，两端显示真实费用 |
| 新手机没有清除 AI 标记，后来的手机可覆盖同一座位；中途加入可清空在局手牌 | 真人座位唯一；仅在结算阶段接受入座，人数调整同时重映射桌面和手机连接并保留筹码 |
| 掉线清空手牌、看牌状态，AI 策略数组索引也可能错位 | 保留整副手牌和座位状态，由对应索引的 AI 接管；当前行动者掉线后及时启动 AI |
| 看牌、无效比牌和未知动作会停止倒计时；手机倒计时每次同步重置为 30 秒 | 房主维护统一 15 秒倒计时，只有实际换回合或结算才重置；无效动作不影响超时弃牌 |
| 尚未看牌的牌值已提前发送到客户端 | 未看牌不发送私有牌值；看牌后仅本人收到，结算后同步全部参局手牌 |
| 旧 TCP 客户端断开后，列表下标变化导致玩家身份错位；AI 行动未持续同步 | 连接使用稳定编号，两种协议共用个性化状态构建，游戏状态变化和倒计时都同步 |
| HTTP 开始后立即展示模态二维码，WebSocket 可能尚未启动；重复建房清空映射 | 全部服务就绪后才展示二维码，重复展示保持房间与玩家状态，端口失败明确提示 |
| HTTP 请求分包时提前解析；短连接缺少清理；心跳只发送 ping | 累积完整请求头后处理，限制请求大小并清理连接；未收到 pong 的连接会被断开 |
| 玩家名称经 `innerHTML` 拼接可变成网页内容；断线后仍保留操作区 | 玩家名与选项按文本渲染，断线禁用操作；发送后等待确认，过期回合请求不会生效 |
| 战绩以奖池作为净盈利、输家损失总为零，最佳牌型被后续弱牌覆盖 | 保存开局筹码，记录真实净输赢；最佳牌型只在更强时更新；存档改用原子替换写入 |
| 桌面一排固定宽度玩家和全部按钮把窗口撑宽；远端玩家的动画与倒计时映射错误 | 可滚动玩家网格、两行工具按钮，按本地座位映射动画与倒计时；调整牌背与状态区样式 |
| 筹码不足后没有补充入口，“再来一局”无法恢复牌桌 | 新增房主“重开牌桌”，选择每位玩家 20–1,000,000 起始筹码；可中止当前局，统一清空奖池、手牌和计时，保留座位与战绩，保存筹码和起始设置 |
| 重开后的手机结算弹窗、待确认操作及旧回合请求可能残留 | 同步牌桌重开编号，清除旧界面状态并拒绝过期回合操作；桌面客户端只接收房主的重开状态 |
| 快速开始下一局时，上一局临时翻开的牌面可能残留 | 新局清除临时展示状态后立即刷新为牌背，旧翻牌回调不能影响新局 |
| VS Code 默认构建任务变成只编译活动文件，启动配置仍指向旧构建目录 | 默认使用 CMake 配置并构建整个项目，调试配置统一指向 `build-review/PokerGame`，保留用户另加的活动文件任务 |

手机页面的 HTML、CSS、JavaScript 已移到 `web/` 并通过 Qt 资源打包，运行时不需要额外网页目录或构建工具。

## 验证

- 使用当前环境 Qt 6.10.2 和 GCC 15.2，以 `-Wall -Wextra -Wpedantic` 编译通过，最后一次构建没有编译警告。
- `ctest --test-dir build-review --output-on-failure`：两个测试套件全部通过。
- Qt 套件包含 18 个功能用例（连同初始化和清理，Qt 汇总显示 20 项通过），覆盖全部 22,100 种三张手牌分类、非法操作、筹码守恒、超时弃牌、真实 HTTP / WebSocket / TCP 回环通信、桌面和手机混合对局，以及重开确认/取消、筹码保存、房主权限、旧回合失效和新局牌面清理。
- 手机 JavaScript 的 7 个用例全部通过，覆盖服务器确认后的看牌、费用翻倍、重复点击保护、过期弹窗、名称文本渲染、断线、新一局状态及牌桌重开。
- 使用无界面 Edge 和模拟对局数据检查 390×844、320×640、844×390 三种视口，没有页面横向溢出或操作区越界。
- 桌面和手机截图位于本地 `build-review/screenshots/`；本轮构建使用独立目录，保留用户测试产生的旧 `build/` 文件变动。

未使用真实手机做跨设备 WiFi 实测。重连仍按新连接在两局之间申请座位，不保证恢复到原座位；下注仍采用原有单奖池规则，不引入边池。操作与运行说明见根目录 README。
